Design system · interaction states

One overlay for every interactive state.

A state layer is a single solid-colour-with-transparency fill, drawn over a component's background to signal hover, focus, pressed, selected and dragged — without inventing a new colour per component, variant, or semantic hue.

RecommendationTint = the content colour (currentColor), not black/white. One active layerHighest-priority state wins. Opacities are never summed. Never the only cueFocus, selection and disabled each carry an independent indicator.

Hover, focus (Tab) or press anything on this page — it is running the real tokens. Use the bar above to test across grounds.

Primary name state layer  ·  documented synonyms: interaction layer, interaction overlay. Use state layer in tokens, code and Figma; the others only in prose.

01

Colour strategy

Two candidates were evaluated. The recommendation is the content colour, expressed in CSS as currentColor.

Option A — black / white by surface

Black at low opacity on light surfaces, white on dark.

  • Works on neutral surfaces.
  • Breaks on saturated fills: black over a blue primary button reads muddy; you actually want white.
  • Needs a light/dark branch to pick black vs white.

✓ Recommended — Option B

Content / foreground colour

The layer inherits the component's own text colour via currentColor.

  • Subsumes A: neutral surfaces have dark/light text → dark/light layer.
  • Correct on semantic fills: a primary button's text is on-accent (white) → white layer over blue.
  • Zero per-component colour tokens; no light/dark branch for the tint.

Trade-off accepted: because the tint follows content colour, the layer opacity is a plain number and can't sit inside light-dark(), so opacities are mode-invariant. High contrast raises them through [data-contrast]. Toggle Violet and Dark above — the overlay tracks each context with no new tokens.

02

Composition model

Every interactive component stacks four layers, bottom to top. The state layer sits between the background and the content, blocks no events, and touches no text.

4
Focus ring  outline, when focused — independent of the layer
3
Content  text, icons — never dimmed or covered by the layer
2
State layer  currentColor @ per-state opacity · pointer-events:none · z-index:-1
1
Container background  the component's own fill or surface

Implemented as a ::before pseudo-element with isolation:isolate on the host, so z-index:-1 lands the layer above the background but below content — no changes to the content markup.

05

Light & dark rules

Tint direction is automatic. In light mode content is dark, so the layer darkens the surface; in dark mode content is light, so it lightens. Both increase separation from the ground — no per-mode colour token, because currentColor already flips.

Opacities stay constant across light and dark. A 7% light-on-dark and 7% dark-on-light read close enough perceptually, and a number can't live in light-dark(). If a team wants a per-mode nudge, override the opacity token under a theme selector.

Saturated grounds. On a primary/danger fill the content colour is on-accent (near-white), so the layer is a white wash on both modes — the correct, expected behaviour for a filled control. Toggle Violet above to confirm it holds when the accent hue changes.

High contrast is handled as an override, not a third value: [data-contrast="high"] raises every opacity and thickens the focus ring, composing with light/dark.

06

Priority & combined states

Exactly one layer is ever active — the highest-priority state. Opacities from different states are never added.

disabled > dragged > pressed > focus > hover > selected > default

When these coincideLayer shownWhy
Hover + focusFocus (0.10)focus outranks hover
Focus + pressedPressed (0.12)pressed outranks focus; focus ring stays visible
Selected + hoverHover (0.07)hover replaces the selected tint; selection shown by its own indicator
Selected + pressedPressed (0.12)pressed wins; selection indicator persists
Disabled + anythingNone (0)disabled forces the layer off entirely

Is selected a persistent base?

Reviewed and declined for v1. Making selected an additive base under hover/pressed means two overlapping layers — effectively summed opacity, which the spec forbids. Instead selected is the lowest rung and hover/pressed replace it; selection never disappears because it always carries an independent indicator (check, filled control, rail, weight). This keeps a single active layer and keeps selection accessible. Teams that truly need a stronger selected+hover can define a dedicated combined opacity token — not a runtime sum.

08

CSS implementation

The whole pattern is one opt-in class. Components add ds-interactive; nothing is hardcoded — colour, opacity, ring and transition all read tokens.

/* patterns/state-layer.css — applies to any .ds-interactive element */
.ds-interactive { position: relative; isolation: isolate; --interaction-layer-opacity: 0; }

.ds-interactive::before {
  content: ""; position: absolute; inset: 0; z-index: -1;   /* above bg, below content */
  border-radius: inherit;
  background: var(--interaction-layer-color);               /* = currentColor */
  opacity: var(--interaction-layer-opacity);
  pointer-events: none;                                    /* never blocks events */
  transition: opacity var(--dur-hover) var(--ease);
}

/* priority ladder — ascending; equal specificity, later rule wins */
.ds-interactive[aria-selected="true"],
.ds-interactive:has(:checked)      { --interaction-layer-opacity: var(--interaction-selected-opacity); }
.ds-interactive:hover              { --interaction-layer-opacity: var(--interaction-hover-opacity); }
.ds-interactive:focus-visible      { --interaction-layer-opacity: var(--interaction-focus-opacity); }
.ds-interactive:active             { --interaction-layer-opacity: var(--interaction-pressed-opacity); }
.ds-interactive[data-dragging]     { --interaction-layer-opacity: var(--interaction-dragged-opacity); }
.ds-interactive:disabled,
.ds-interactive[aria-disabled]     { --interaction-layer-opacity: var(--interaction-disabled-opacity); }

/* independent focus indicator */
.ds-interactive:focus-visible {
  outline: var(--interaction-focus-ring-width) solid var(--interaction-focus-ring-color);
  outline-offset: var(--interaction-focus-ring-offset);
}
@media (prefers-reduced-motion: reduce) { .ds-interactive::before { transition: none; } }
09

React component

No state colours in the component — it only sets structural classes and forwards ARIA. The layer is entirely CSS-driven, so it needs no JS for hover/focus/press.

// Button.tsx — a headless-ish button that opts into the state layer
type Props = React.ButtonHTMLAttributes<HTMLButtonElement> & {
  variant?: "primary" | "neutral" | "danger" | "ghost";
  selected?: boolean;
};

export function Button({ variant = "neutral", selected, disabled, children, ...rest }: Props) {
  return (
    <button
      className={`ds-button ds-interactive ${variant}`}   // no colour logic here
      data-variant={variant}
      aria-selected={selected || undefined}               // drives the selected layer
      aria-disabled={disabled || undefined}
      disabled={disabled}
      {...rest}
    >
      {children}
    </button>
  );
}

// Dragged state (e.g. from a DnD lib): toggle the data attribute, not a style.
<li className="ds-list ds-interactive" data-dragging={isDragging || undefined} />
10

Figma recommendations

  • Variables collection "interaction". Number variables for each opacity (hover 0.07…), a colour variable for the tint, and dimension variables for the ring.
  • Tint = the mode-aware "on" colour. Figma has no currentColor, so bind the state-layer fill to on-surface for neutral components and on-primary for filled ones. Two modes (Light/Dark) on the collection cover the tint flip.
  • One "State layer" component. A frame set to Fill container, fill = tint variable, layer opacity = the state's number variable. Drop it as the top layer of each interactive component and switch its opacity variable per variant.
  • Component states as variants, not detached copies: a State property with Default / Hover / Focus / Pressed / Selected / Disabled, each binding a different opacity variable.
  • Focus ring is a separate effect/stroke bound to the ring variables — never faked with the state layer, mirroring the code.
11

Accessibility criteria

The state layer is never the only signal. Each of these carries an independent indicator that survives when the layer is replaced or removed:

MeaningIndependent indicator (not the layer)
Keyboard focusVisible focus ring (outline), ≥3:1 vs adjacent, offset for clarity
SelectedCheck / filled control / active rail / underline / weight
ErrorBorder colour + icon + message — semantic danger, not a red wash
DisabledDimmed content tokens + aria-disabled; layer forced to 0
Critical state changeText/icon change + announced update, not opacity alone
  • Contrast: the layer only shifts luminance slightly; text keeps its own token contrast (≥4.5:1). The focus ring is checked at ≥3:1 across every brand by the validator.
  • High contrast: opacities and ring width bump under [data-contrast] and prefers-contrast: more.
  • Keyboard: focus uses :focus-visible, so a mouse click never leaves a lingering focus layer; Tab order is untouched by the pointer-events:none layer.
  • Reduced motion: under prefers-reduced-motion: reduce the opacity fade is removed — the state still appears, just instantly.
12

Edge cases & risks

Native inputs

::before won't render on <input>. Put ds-interactive on the label wrapper; drive selected/focus via :has(:checked) / :has(:focus-visible).

currentColor surprises

If a component sets an unusual text colour, the layer follows it. Override --interaction-layer-color locally when the tint shouldn't equal the text.

Rounded corners

Layer uses border-radius: inherit. A component with a differently-clipped background needs overflow:hidden or a matching radius on the layer.

z-index / stacking

Relies on isolation:isolate + z-index:-1. A host that sets its own low z-index children can collide — keep the layer's host free of negative-z content.

Transparent hosts

On a ghost/transparent component the layer tints whatever shows through. Usually fine; verify over busy backgrounds.

Specificity override

The priority ladder relies on equal specificity + source order. A consumer selector more specific than .ds-interactive:state can break the order — document it.

13

Progressive adoption

  1. Land the tokens. Add the interaction.* semantic tokens to the system; ship no behaviour yet. Non-breaking.
  2. Ship the pattern as opt-in. Add patterns/state-layer.css. Existing components are untouched until they add ds-interactive.
  3. Migrate one archetype per PR. Start with list/nav/menu items (no existing hover colour to unwind), then filled controls (buttons) where the layer replaces per-state background tokens.
  4. Retire the old hover/pressed colour tokens per component as it migrates; the validator's tier + contrast checks keep each step honest.
  5. Update Figma in lockstep (§10) so design and code read the same token names.
  6. Enforce. The CSS-native validator already covers refs, tier direction, mode completeness and contrast across brands — no state layer can reach a raw ramp or skip a mode.
